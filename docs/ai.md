# AI в разработке

> Обязательный раздел задания. Заполняется по факту работы, а не заранее.
> Процесс: мультиагентная разработка — на каждую из 13 задач плана отдельный
> агент-имплементер пишет код по брифу, дифф проверяет независимый агент-ревьюер,
> по завершении этапа — финальное ревью всей ветки. ~95% кода репозитория
> сгенерировано; руками/контроллером — архитектурные rulings и приёмка.

## Что генерировали

**Этап 01 (scaffold → рабочее дерево):**

- Инфраструктура и конфиги (vite/tsconfig/vitest, алиасы, тема, провайдеры) — генерировал агент по плану; руками проверялись значения контрактов (staleTime 5000, пороги цветов, shape узла).
- Mock-сервер целиком: генератор данных (seeded PRNG, 45 узлов), SSE-хаб, мутации, heartbeat — AI; тонкости (отписка на disconnect, clamp-границы) покрыты его же property-тестами.
- Data-слой (zod-схема, fetchOrgTree, кэш-хук) и domain-слой (buildForest, DataError) — AI по TDD: тесты писались до реализации, RED→GREEN зафиксирован в отчётах задач.
- Компоненты дерева и состояний — AI; a11y-атрибуты (role tree/treeitem/group, aria-expanded) проверены тестами компонента.
- Unit-тесты (56 шт. к концу этапа) — AI; каждая правка после ревью проходила повторный прогон покрывающих тестов.

**Этап 02 (агрегация + таблица):**

- `aggregateForest` (один post-order DFS, взвешенное среднее без compounded-округлений), `recomputeBranch` (инкрементальный пересчёт ветки, identity вне dirty-set) — AI по TDD; 9 тестов RED→GREEN + ревью-фикс эквивалентности recompute ≡ full.
- `MetricsTable` (сортировка клик/double-click, фильтр с дебаунсом 250мс, формат `12 345 678 руб.`), split-view ≥1280px, связь «клик по строке → выделение в дереве + раскрытие пути» — AI; 98→101 тест.

**Этап 03 (SSE realtime + polish):**

- Клиент SSE: patchSchema (zod), `applyPatch` без полного рефетча, `connectSse` с экспоненциальным backoff 1→16с ±30% jitter, ConnectionBadge — AI; тесты точных задержек backoff.
- Инкрементальная агрегация при патчах + fade-out изменённых ячеек (value-diff по снапшоту, 1.5с, reduced-motion) — AI; keyframes-анимация раскрытия дерева через grid-template-rows с `inert` на свёрнутом.
- Keyboard navigation по таблице (стрелки/Home/End с real DOM focus) — AI; 147 тестов к концу этапа.

**Этап 04 (инфраструктура + AI-поиск):**

- Docker (multi-stage Dockerfile.client / Dockerfile.server), nginx (gzip, immutable-кэш ассетов, SPA-фолбэк, SSE-прокси без буферизации), compose с healthchecks — AI; манифест проверен `docker compose config`, затем живьём.
- `scripts/check-size.mjs` — гейт бюджета бандла (gzip-сумма ≤ 200 КБ), встроен в `pnpm build`; 7 тестов RED→GREEN.
- AI-поиск: `parseNaturalQuery` — детерминированный RU-парсер естественного языка (бюджет с «млн/тыс/к», численность, эффективность, уровень; combined AND; fail-closed → fallback текстового поиска), «распознано: …»-hint — AI; 34 теста парсера, 190/190 суммарно.
- Тулчейн-конфиги (`.oxlintrc.json`, `.oxfmtrc.json`, husky + lint-staged) — AI; pre-commit hook проверен живьём в обе стороны (блок коммита с ошибкой + авто-формат).

## Что переписали руками и почему

_(«руками» = решения контроллера/ревьюеров вне кодогенерации; правки кода — через агентов по findings)_

- **validateForest перенесён из data- в domain-слой**: ревьюер поймал нарушение слоёв (функция была мёртвым кодом в schema.ts) — архитектурное решение принял контроллер, код переписан отдельным коммитом `b01e595`.
- **DataError больше не крашит рендер**: ревьюер нашёл, что ошибка валидации леса не доходит до ErrorState (белый экран) — обёрнута в try/catch внутри useMemo, не-DataError по-прежнему пробрасывается (`cf756ce`).
- **Expansion дерева сбрасывался при каждом refetch**: найдено финальным ревью ветки, а не тестами — фиксировалось переходом undefined→forest (`50eb50d`), потому что stage 02 строит на этом состоянии выделение строк.
- **SSE-запись без обработки ошибок**: ревью указало на возможный ERR_STREAM_DESTROYED при гонке broadcast/disconnect — добавлен `res.on('error', unsubscribe)` (там же).
- **Стек новее плана (ruling контроллера)**: React 19 / Vite 8 / TypeScript 7 native вместо «React 18, Vite 5» из плана — актуальные create-vite-версии на момент старта; TS7 native потребовал пересмотра плана линтинга (см. ниже), но tsc/билд/тесты на нём зелёные.
- **Toolchain-замена (ruling пользователя)**: ESLint 9 + Prettier → **Oxlint + Oxfmt**. Обоснование: оба на Rust (линт репо ~0.3с на 53 файла), а главное — type-aware правила (`no-floating-promises`, `no-unsafe-*`…) выполняет `oxlint-tsgolint` поверх typescript-go, т.е. тот же TS7, что и `tsc` в репо. Старый путь требовал side-by-side пина TS 6 через `.pnpmfile.cjs` (typescript-eslint 8 жёстко падает на TS 7) — хак удалён вместе со стеком ESLint (`de3488d`).
- **Баг `gzip_min_length` в nginx найден только live-проверкой**: `gzip_min_length 1024`, а собранный `index.html` — 322 байта, т.е. точка входа SPA отдавалась без сжатия. Статическая выверка конфига и `docker compose config` этого не ловили; поймал curl на живом стеке, порог снижен до 256 (`5357c15`). Там же — crash-loop серверного контейнера: exec-form `CMD ["tsx", …]` не видит `/app/node_modules/.bin`, добавлен `ENV PATH` (findings live-прогона, исправлены через агента).

## Честная оценка

AI сгенерировал ~95% кода. Ключевую ценность дала не генерация, а процесс вокруг неё:

- Независимые ревью на каждую задачу поймали три архитектурных дефекта (нарушение слоёв, краш рендера, сброс состояния UI) — без них регрессии дожили бы до этапа 02+.
- Две ошибки инфраструктуры (nginx gzip, CMD tsx) не поймал ни один статический чек — только живой прогон стека. Генерация «по плану» с валидацией конфига выглядели зелёно и были бы закрыты как done.
- Часть находок — процессные, а не кодовые: типизированные моки тестов после миграции на oxlint, снятие подавления там, где новое правило не флагает кейс.

Генерация «в лоб» без ревью-цикла и live-верификации дала бы формально работающий, но менее надёжный результат — и медленнее: находки дешевле фиксить в момент ревью задачи, чем после интеграции этапа.
