# ADR-002: SSE для live-обновлений

**Статус:** принято

**Контекст.** Задание допускает WebSocket, SSE или «эффективный поллинг». Сервер шлёт
только однонаправленные патчи; поллинг явно расточителен при редких изменениях.

**Решение.** SSE (`EventSource` на `GET /api/events`). Реконнект реализуем сами:
экспоненциальный backoff 1→2→4→…→16с c jitter ±30%, т.к. нативный autoretry EventSource
не даёт контроля индикатора состояния.

**Альтернативы.**

- _WebSocket_ — нужен отдельный протокол/библиотека на сервере и ручной heartbeat;
  для one-way патчей избыточен. Двусторонность не требуется (клиент только читает).
- _Поллинг_ — требования к «эффективности» выполняются только с адаптивным интервалом;
  всё равно каждый запрос тянет валидацию полного ответа. Отклонено.

**Последствия.** HTTP/1.1 лимит 6 соединений с одного origin — в dev учитываем (одно SSE,
запросы GET проходят); для prod Nginx: `proxy_buffering off` на `/api/events`. Патчи —
JSON по схеме из `docs/data-model.md`.
