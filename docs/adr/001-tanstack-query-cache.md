# ADR-001: TanStack Query как слой кэширования

**Статус:** принято

**Контекст.** Задание требует слой кэширования со stale-while-revalidate, stale time 5с,
дедупликацией запросов и инвалидацией только при реальном изменении данных. Альтернатива —
самописный кэш на useRef/Context.

**Решение.** TanStack Query v5 (`@tanstack/react-query`), единственный query-ключ
`['org-tree']`, `staleTime: 5000`, `retry: 1`. Инвалидация — только по SSE-патчу
(`setQueryData`), без refetchInterval.

**Альтернативы.**
- *Самописный кэш* — «минимум задания», но нужно вручную решать дедупликацию, гонки
  ответов, GC кэша; это готовые баги. Отклонено: стоимость выше пользы.
- *RTK Query / SWR* — RTK тянет Redux (лишняя зависимость без стора), SWR слабее в
  программной инвалидации и `setQueryData`-патчах, которые нам нужны на этапе 03.

**Последствия.** +12 КБ gzip к бюджету бандла (учтено, бюджет ≤200 КБ соблюдается);
одна внешняя зависимость; live-патчи ложатся на поддерживаемый API `setQueryData`.
